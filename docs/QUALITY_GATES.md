# 验收标准与低成本测试计划

## 一、验收规则与状态报告

每项用 `PASS (代码+必要实机验证)` / `IMPLEMENTED_UNVERIFIED` / `DEGRADED` / `EXPERIMENTAL` / `BLOCKED` / `NOT_IMPLEMENTED` 标明。禁止以“编译通过”代替“实际 AirPods/录像/备份通过”。

### P0 阻断核心

| 编号 | 场景 | 最低可接受结果 |
|---|---|---|
| P0-01 | 无网络 iPhone 导入本地已制伴奏 | 可试听、半音变调、速度基本保持，歌词可显示 |
| P0-02 | 单设备前置镜头+麦克风+耳机播放 | 人声/视频真实可录，伴奏输出路径可核查；若 AirPods 高质量不可用有明确备用麦克风/路线 |
| P0-03 | 默认 3s 倒计时和完整唱歌 | 录制画面和干声独立可恢复，时间信息可对齐，不出现不可解释的大幅固定延迟 |
| P0-04 | AirPods 断开/路由切换 | 不突然将伴奏大声外放，已写内容保存，允许恢复或结束 |
| P0-05 | 正常停止与多 Take | Take 01 不因录 Take 02、切换预设或导出而被覆盖，立即可预览 |
| P0-06 | 混音与字幕 | 人声/伴奏独立调整、简易混响 EQ，带/无字幕两个变体的实际内容匹配选择 |
| P0-07 | 默认 1080p 导出 | 最终视频可播放，声音/视频对齐，导出失败不影响原始数据 |
| P0-08 | 录制中断/低空间 | 至少保护已经完成的片段（在技术允许范围）；危险空间前保护性停止且不删除任何源素材 |
| P0-09 | 完整工程导出再导入另一设备 | Song、Arrangement、Take、歌词、编辑参数和全部必需素材能够重新读取编辑 |
| P0-10 | 精简/自定义备份与冲突 | 排除旧 Take 不破坏引用；冲突先保存副本；无空间不能无保护覆盖 |
| P0-11 | 云端保存和归档状态 | 文件选择器成功仅显示“已导出”；未远端验证时明确警告、二次确认才释放本地空间 |
| P0-12 | 摄像头不可用 | 提供纯音频正式录制或权限修复，不出现死按钮 |

### P1 高阶功能条件开放

| 编号 | 能力 | 放行条件 / 降级 |
|---|---|---|
| P1-01 | iPad 本地双 stem 分离 | 设备/模型可运行，处理结果可试听、重试、保留版本；无法运行则建议导入伴奏 |
| P1-02 | 强制歌词对齐 | 有可信音轨且对齐质量可用；否则粗略滚动和人工标记 |
| P1-03 | 逐字高亮 | 可信逐字时间轴才开放；否则自动逐句 |
| P1-04 | 轻度自动修音 | 与原声 A/B 对比自然、调性正确、可关闭/撤销；失真时默认关闭/标记实验 |
| P1-05 | 断线后建议拼接点 | 可预览、可调整，不伪装自动无痕 |
| P1-06 | 4K | 仅设备捕获、编辑及导出完整支持时出现，不虚报分辨率 |
| P1-07 | 高质量 AirPods | 运行时能力检测成功才显示开启，不得用耳机名称硬编码支持 |

## 二、轻量测试（用户明确不要大型回归体系）

**开发期间：** 只对纯逻辑做短小测试：半音/时间轴变换、LRC、文件哈希、压缩包安全、备份依赖闭包、冲突状态机、导出预设、录制状态转换。不要设置数十种冗余 UI 自动化测试。

**集中构建 1：** 项目整体编译/依赖检查，可在 GitHub Actions 手动 `workflow_dispatch` 运行一次里程碑 macOS Xcode build（不需要每次 push 运行）。签名未配置可先验证无签名构建，但要如实报告不能安装。

**实机冒烟 1（P0 音视频）：** 选择一首 30～60 秒自有音频样本，用 iPhone+AirPods 录制、停止、预览、重复录制、导出；检查人声、视频和伴奏有无系统级明显失同步/重复输入。重复一次使用设备麦克风备用路径。

**实机冒烟 2（P0 数据）：** 将已生成工程完整备份到 Files，再导入 iPad，打开编辑、导出；测试小范围精简和自定义备份；模拟录制时 AirPods 断线、空间预警（不破坏真实用户资料）。

**高级模块抽样：** 各选一段短授权自有样本做 AI stem、逐句/逐字歌词、修音 A/B、4K；没有实机时标记未验证，绝不可报告 PASS。

**集中构建 2：** 完整功能整合后统一重新构建及签名验证。不要求每做一个新页面就出 IPA。

## 三、可量化但不过度承诺的标准

- 工程包哈希/依赖校验必须全部通过，发现缺失直接阻止覆盖式导入。
- 未完成的导出任务若部分成功，保留已有产物和失败项诊断。
- 音视频同步的可接受偏移可由工程测试记录（不同设备/路由/时长），根据用户听感与样本审查，不在未测前编造统一毫秒精度承诺。
- 空间安全阈值按文件大小、码率、缓冲和系统可用容量动态计算；不凭空指定一个对所有设备都适用的安全数字。
- 任何模拟 AI 或虚构录制进度都不属于合格实现。

## 四、最终交付清单

- 可编译原生源代码、配置和签名/安装说明；必要时 IPA 产物（仅真实签名后）。
- `IMPLEMENTATION_ADR.md`（如修改了建议架构）、`THIRD_PARTY_NOTICES`。
- 核心 P0/P1 功能状态表、已知限制、系统版本/机型支持表。
- 简短测试记录：设备型号、系统版本、AirPods 型号/音频路由、实际是否测试、结果/失败。
- 工程存储格式与用户备份/恢复操作说明，以及“Google Drive 保存≠远端验证”的重要提示。
