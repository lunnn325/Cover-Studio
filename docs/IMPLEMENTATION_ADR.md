# My Cover Studio V1 实施决策

产品要求以 DECISIONS.md 为准。以下是技术实现决策，不代表媒体能力通过实机验收。

## ADR 001：原生应用与可复现项目

问题：主要开发环境是 Windows，缺少 Xcode，需要可复查且依赖少的原生项目。

候选：XcodeGen/Tuist、手写持续维护 pbxproj、确定性生成器。

决策：SwiftUI application + 本地 CoverCore Swift Package；Python 标准库生成并提交 Xcode 工程和共享 scheme。iOS/iPadOS 17 起运行，Swift 5 语言模式，Xcode 26 SDK 编译。只使用 Apple 系统框架。生成器扫描 App 目录，避免新增源文件漏进 target。

兼容性：保持原生 iPhone/iPad、相同领域模型、离线核心能力。无服务端、账号、分析或收费依赖。iPad 编辑页按可用窗口宽度分栏，紧凑窗口保留同一编辑控件。

验证：跨平台配置检查；macOS 集中 swift test 和无签名 Simulator build。真实签名/实机仍独立验收。

## ADR 002：单一路径采集与可恢复片段

问题：相机和独立音频引擎同时采麦克风容易争抢资源，独立 start 调用也不能证明同步。

决策：AVCaptureSession 是唯一麦克风输入；AVCaptureAudioDataOutput 写独立干声 M4A（48 kHz / 单声道 / AAC 256 kbps，未加效果），AVCaptureVideoDataOutput 写无音轨的 H.264 MOV。AVAudioEngine 只播放伴奏，不读取 inputNode。各流 firstPTS 归零写容器，同时保存共同 host anchor、原始首采样 PTS、歌曲位置、播放 hostTime、实际路由和输入/输出延迟。渲染按 firstPTS−anchor 补前导差，不假设两个文件从零就同步。

每约 8 秒轮换片段，视频 MOV 另启用初始 1 秒/后续 2 秒 movie fragments。片段封装后才计算大小/哈希并提交工程。空间预算起初使用保守预设，随后按已提交片段的实际字节/时长乘安全系数上调峰值，不在同一轮录制降低阈值。索引失败会传播到结束状态，保留 journal，不报告成功。容器正在写入的最后片段可能不可恢复；不保证崩溃零损失。正常停止后直接合成已封装的干声/画面做原始预览，不等待字幕/混音渲染。

兼容性：所有 Take 与源素材独立保存，不覆盖旧录制。恢复接唱生成新片段，重叠按后录片段替代，原件保留，切点可手动调整。耳返默认关闭，仅从现有 AVCapture PCM 流转换后交给独立播放节点，不新增麦克风路径。仅系统明确报告有线耳机、采样可转换且延迟门槛满足才可手动开启；蓝牙和 USB 默认降级关闭，发生路由变化/队列积压/格式失败即关闭。实际声学延迟和蓝牙输出安全性必须实机检查。

重开后从 recording.json 找到已提交 Take，作品库提供预览/重新检查后接唱，保留该 Take 的原伴奏版本和变调。片段增加可选 take-local sequence（旧包缺字段仍可读），不依赖设备 uptime 排序；这同时解决媒体 finalizer 回调乱序和设备重启后的 host clock 重置。最后未完成容器仍不保证可修复。编辑撤销会跳过已永久删除依赖的历史图，不恢复无效引用。

## ADR 003：非破坏编辑与顺序导出

决策：编辑图保存音量、EQ、高通、混响、固定偏移、首尾裁剪、镜像、构图、字幕和切点。Take 固定绑定录制时的 Arrangement 与整数半音。播放和离线混音均使用 TimePitch pitch=半音×100、rate=1；不把它用于自动修音。

TimePitch 输入/输出均显式使用源文件 processingFormat，由 mixer 转到输出格式；offline mode 在构图前开启，避免默认硬件 44.1kHz 格式改变 48kHz 源播放时钟。运行时检查 effect 两侧格式，拒绝不匹配输出。实际合成检查从错误版本 240.417 Hz 修复为 261.658 Hz（220 Hz 升三半音，预期 261.626 Hz），时长保持两秒。此证据不代替真人音乐听感或实机播放验收。

AVAudioEngine offline 渲染混音；AVMutableComposition/VideoComposition 组合画面。字幕使用 CoreText 栅格与 Core Image 按帧时间戳叠加，仅缓存当前一句的小图。先合成可复用的无字幕基础画面，带字幕版本再烧录；无字幕成品直接复制基础文件，不重复编码。选中的照片通过真实视频帧生成静态背景。补拍只捕获相机，不读取麦克风，参考成品或伴奏，保存为独立 visual asset；不替换正式人声。

运行依据：`795f2f2` 的模拟器报告已越过离线混音和照片生成，在带字幕视频阶段进程退出，未拿到有效崩溃栈，不能断言具体系统根因。原 Core Animation 路径改为可逐帧检查的 Core Image 路径，并增加阶段、进程/系统诊断和中英文输出帧验证。Apple 提供[按帧 Core Image composition](https://developer.apple.com/documentation/avfoundation/avmutablevideocomposition/videocomposition(with:applyingcifilterswithhandler:completionhandler:))；[CIContext 文档](https://developer.apple.com/documentation/coreimage/cicontext)说明可跨线程共享 context/image。代价是字幕版增加一次基础文件读取/编码，空间预算涵盖临时画面；不改变双版本、原件和手工时间轴需求。

基础降噪明确采用高通减少低频杂音，不冒称全频 AI 降噪。默认视频 1080p/30；方形为 1080×1080，不放大到所谓 4K。混音和干声/伴奏输出可选 M4A 或 48kHz float PCM WAV。顺序队列逐项保存状态，失败不删除源文件或完成项，只有可重建的操作临时文件自动清理。歌词缺少可信逐句时间点时不开放字幕成品；字幕范围和补拍画面偏移独立保存。保留有限的本会话编辑撤销栈，原始音轨不受影响。

## ADR 004：COVERP01 流式工程包

问题：大型音视频不适合 FileDocument 一次装入内存；ZIP 还会增加解压路径与压缩炸弹风险。

决策：.coverproject 是开放的未压缩流式容器，不使用 ZIP 或第三方归档库。结构为 8 字节 magic `COVERP01`、8 字节大端 JSON 长度、32 字节清单 SHA-256、JSON manifest、按清单顺序排列的原始素材字节。清单内包含完整工程模型、schema/minReader/appVersion、功能标志、工程/归档/设备身份、revision、每素材相对路径/大小/哈希、采样属性和有理数时间。

限制：清单 16 MiB、素材 20,000 个、总字节最多 512 GiB，同时受实际磁盘空间限制。拒绝路径遍历、控制字符、符号链接、目录/文件冲突和大小写/Unicode 同名覆盖。只允许媒体路径，不能覆盖工程索引。输入无解压步骤，不接受 ZIP 伪装。

完整包默认排除可重新生成成品，可明确勾选；精简/自定义保留编辑依赖闭包。包生成后重新流式读取校验才发布。恢复先暂存并校验全部长度/哈希/引用/版本，再提交目录。同 ID 默认保留安全副本；替换实现使用同卷重命名保留 `.safety-*` 原目录与恢复事务日志，失败/重启可回滚。复制工程不覆盖历史索引。

迁移：当前仅 schema 1；未来版本/未知功能明确拒绝，不能丢字段后继续导入。格式细节见 USER_GUIDE.md。

## ADR 005：备份证据与删除边界

决策：准备包、Files 接收、外部包恢复验证各自记录，不称云端上传成功。备份记录不推进工程内容 revision；只有内容修改才推进。释放空间要求当前 revision 已交给 Files 或验证恢复。UI 展示包类型和排除的 Take，用户两次确认后才移除本工程源素材。精简包排除的旧 Take 在释放后无法从该包恢复，必须在确认中明确告知。

待恢复录制 journal 存在时拒绝释放源素材，先完成恢复/结束录制并重新备份；损坏 journal 也不能绕过保护。恢复的已登记导出成品与再次扫描到的同路径文件只登记一次，避免重新备份产生重复引用错误。

所有素材为工程私有路径；不同工程复制时复制素材，避免跨工程删除共享文件。Take 删除检查其他 Take、编辑、伴奏和照片引用，共享片段保留。操作不自动删除原始素材。安全副本/失败恢复暂存不自动清理；存储页允许校验导出有完整索引的副本，再从外部包恢复。删除所选副本必须两次确认，且有未完成恢复事务时禁止操作。

## ADR 006：P1 能力诚实关闭

AISeparationProvider、LyricsAlignmentProvider、PitchCorrectionProvider 提供可替换协议，目前 UnavailableAI 明确不可用。无模型下载、云 API 或上传。逐字与智能切点没有伪造实现；P0 手工歌词与切点替代。4K 未通过完整捕获/编辑/输出验证而关闭。

高质量蓝牙仅在 SDK/iOS 26 条件下请求，并读取系统 Bluetooth microphone extension 的 supported/enabled；不根据 AirPods 名称硬编码能力。支持 API 存在不等于真实音质已通过测试。

## ADR 007：集中验证成本

GitHub Actions 仅 workflow_dispatch 或 PR opened/ready_for_review 里程碑运行，不在普通 push/synchronize 上运行。macOS 单一构建任务执行纯逻辑测试及无签名通用模拟器构建；首次 PR 可同时采集 iPhone/iPad 空状态的浅色/深色与大字号截图。媒体路径修复可选 media_smoke_only，只冷启动一个模拟器而不重复截图。没有大型 E2E 矩阵，不生成未签名假 IPA。

Apple 签名材料未提供；没有真实设备时所有媒体/文件提供者/恢复的实机 gate 保持未验证。已运行证据单列 DELIVERY_STATUS.md。

## ADR 008：编辑页画面预览

问题：已有原始 Take 播放与后期混音试听，但用户必须先导出才能检查字幕、裁切与补拍组合，无法充分校准 Studio Cover。

决策：新增编辑页画面预览，冻结当前参数快照，复用真实混音、VideoComposer 和逐帧字幕管线。无字幕时 AVPlayerItem 直接播放编辑 composition；带字幕时先准备基础画面，再由原生播放器按时间戳叠加同一个字幕 renderer。预览不调用成品队列，不改导出预设、已完成成品或工程版本。

每次预览只持有自身 `cache/preview-UUID`；关闭时先释放播放器，再删除自身可重建缓存。失败/取消也清理该目录，进程意外终止时余下缓存可从存储页清理。空间按时长和画面处理预算预先检查。生成时禁用冲突的编辑/切换/导入/恢复/录制入口，防止同一操作混用两个工程状态。

验证策略：复用已经通过的五种导出和工程恢复证据，本次单独检查新的 AVPlayerItem 路径：1.5 秒方形裁剪、镜像、两个真实字幕帧、音视频轨、源文件哈希、原导出队列不变及关闭后缓存释放。帧生成不等于交互播放器和真实听感通过；设备验收仍独立保留。

## ADR 009：持久成品目录与自定义输出选择

问题：queue.json 只记录当前一轮导出。重建队列后，旧成品虽然未删除，却可能从存储管理和“包含成品”备份中消失。

决策：保持当前队列用于进度/重试，新增 exports/history.json 持久保存已完成文件的记录。队列发布前先合并旧/新完成记录并原子保存，按规范化相对路径去重，不能将另一个工程的内存队列写入本工程。ExportJob 的 JSON 字段保持原样，旧队列无需迁移模型即可读取。

成品目录扫描实际文件，以历史完成记录、当前完成项或恢复工程内的 export 资产为依据；无完成证据的文件单独列为“未登记”，不因文件名或存在就宣称成功。目录展示大小/时间/文件名，提供原生预览、单文件 Files/分享及两次确认删除。歌词按 UTF-8 有界读取；损坏或索引无法读取时明确失败并保留文件。删除限制为 exports 下的媒体/歌词，拒绝路径逃逸、符号链接和元数据；先检查工程引用，保护源素材与其他版本。

备份可包含所有历史已完成项。自定义包可逐个选择，依赖闭包仍强制保留被用作伴奏/画面等的输出；不存在的选择明确失败。归档不复制队列/历史 sidecar，而以素材清单中的 export 角色携带完成文件；恢复后可以重新识别。备份类型或选择改变即使待保存包失效，不能拿旧包冒充新选择。

queue.json/history.json 都是保留的元数据路径，不允许工程资产覆盖。未登记文件不自动加入备份，UI 明确说明可先单独保存到 Files。验证限于短小文件系统/依赖测试与必要原生编译，不重复模拟器媒体渲染。

“释放本地源素材”仅移除非 export 资产；历史成品可能没有包含在所选包里，因此不能顺带删除。已导出文件继续在归档工程的成品目录可用，只有独立的二次确认删除才移除。释放前显示的数量/字节只统计源资产；测试同时核对源文件释放与已导出两版本保留。

## ADR 010：复制快照与未登记原件保留

问题：复制原先按已登记资产估算，却复制整个目录；缓存、历史成品和未登记尾段会让实际占用超过预检。复制失败的 .duplicate 暂存未出现在存储页。中断记录也只能重新检查设备后继续，无法在没有麦克风权限时保留已有内容并结束。

决策：按真实普通文件清单计算复制预算，排除可重建 cache，保留原始文件、未登记尾段、历史成品和日志；拒绝符号链接/特殊文件。复制后核对所有登记素材大小与 SHA-256，最后才写新工程及 previous 索引、提交目录。失败原工程不变，暂存纳入双重确认管理。副本使用新的工程/分支 ID，待恢复列表按工程+Take 组合标识。

结束待恢复记录不调用采集会话。先复制原日志到 media，以 source 角色登记未登记字节、保存工程，最后清除 pending marker。无法关联 Take 的日志也可保留；不创建虚构 Take、不猜测时序、不承诺修复损坏容器。未知原件 duration=0 表示没有可信媒体时长，不能作为成功录制的证据。

存储页列出未登记和已登记但未引用的 media 原件，可另存 Files、尝试实际容器预览、登记进完整包，或两次确认删除。删除再次检查所有伴奏/Take/当前画面依赖，并在待恢复记录存在时拒绝。登记只保存原始字节及哈希；精简/自定义可能排除未引用原件，备份和释放提示补充排除的源文件数量。

安全副本生成完整包时也纳入未登记 media 字节；无有效索引或不完整素材仍明确失败，不把原件保留冒充可播放/同步。验证集中在纯文件系统、哈希、包往返和必要编译，真实录制异常仍待实机。

## ADR 011：字幕描边与旧工程兼容

问题：基础字幕已有阴影，但没有独立描边宽度。决策：保留现有 Core Text 逐帧合成器，增加 0–6 输出像素的黑色描边，与阴影分别调整；按字号换算为负百分比，保留文字填充。依据 [Apple kCTStrokeWidthAttributeName](https://developer.apple.com/documentation/coretext/kctstrokewidthattributename)。不引入新的绘制后端或重复音视频编码。

新增字段保持 schema 1 向后可读，缺少字段时默认 0；旧样式不因更新出现描边。位图额外扩边，并抵消位置偏移，不改变原文字换行/锚点。工程参数校验限制字号、位置及描边范围，拒绝非有限值。备份完整保存参数；轻量兼容/往返检查与复用画面的中英文描边帧比较用于验证，真实设备显示和成品观看仍待验收。

启用描边的包声明必需功能标志 `subtitle-outline`，旧 reader 按既有未知功能规则拒绝，避免静默丢失样式；描边为 0 的包保持旧功能集合。新 reader 可读没有该字段的早期 schema 1 工程。
